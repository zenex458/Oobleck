# Contribution guidelines
Thank you for considering to contribute! We accept contributions from any skill level, as scripts are largely self-contained newer contributors can enjoy a low-stakes environment to work in.

## Steps to contribute 
1. Find or make an issue
The "good first issue" tag is a good place to look for newer contributors.

If your idea for a contribution isn't already in the issues list, you can make an issue.

For some, this is where the contribution process ends! But, if you want to work on the issue yourself, make a comment asking for assignment.

2. Create a fork and a branch to work on the issue
**After** you've been assigned to the issue, you can create a fork of Oobleck. On this fork, make a new branch named after the issue/feature that you're adding.

3. Work on the issue

4. Open a Pull Request from your fork's branch
Ensure to describe *how* you solved the problem, and why you made those decisions.

From there, simply respond to the comments of pull request. The path from here on out will be slightly different depending on the nature of the issue or feature.

## Respecting other contributors
Compared to other open source projects our contribution process is quite relaxed. We don't require you to follow strict naming/description guidelines and we don't enforce any strict guidelines on code style. However, we do ask you respect other contributors and the open source commmunity:

**Look at the issue list and open PRs before working on contributions**. Someone else may have taken the issue and worked on it, or may be in the process of brainstorming fixes in issue comments.

**Wait for assignment**. Please **don't** work on issues you haven't been assigned to, or work on new features without creating an issue and having a maintainer accept it. If you don't then you risk your work being rejected.

**Ask!** We're open to discussion, please comment on issues or PRs and ask for clarification if anything in uncertain!

**Use AI tools responsibly**. We don't tolerate low quality AI contributions. As a rule, AI should only be used to point out critical vulnerabilities within the application - generating code, issues or PRs using AI is heavily discouraged and may result in your issue/PR being closed.
